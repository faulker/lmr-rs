## Design Context

### Users
Operators and developers who already run `lmr-rs serve`. They open a browser to try a System One document (state + typed questions) without assembling curl. This is a local or self-hosted console, not a consumer chat product and not the myphin end-user flow.

### Brand Personality
Precise, editorial, quiet. Three words: **slate, porcelain, verdict**. The interface should feel like a decision instrument: you compose a document, you get a judgement. Confidence comes from typography and the answer itself, not from chrome.

### Aesthetic Direction
Cool porcelain ground, slate-blue ink, a single pine-green accent reserved for the chosen answer. System `ui-serif` for the wordmark and the verdict; `ui-sans-serif` for chrome; `ui-monospace` for JSON. Light by default, `prefers-color-scheme: dark` at night. Two-pane compose | result on desktop, stacked on a narrow viewport.

Anti-references: Inter, purple-to-cyan glow, glassmorphism, chat bubbles, metric-card dashboards, Google Fonts (the binary stays local-first).

### Design Principles
1. The verdict is the hero, not the form chrome.
2. JSON is a working surface, not a dump: live validation on the left, typed rendering on the right.
3. Space over boxes. Do not wrap every region in a card.
4. One accent color, used only for the selected answer and the primary action.
5. Login is a page state, never a modal.
